# 海龟画廊 · 持续升级路线图

[返回画廊](../README.md) · [创作面板与配方](CREATION_GUIDE.md) · [代码创作指南](CREATIVE_GUIDE.md) · [贡献指南](CONTRIBUTING.md) · [提交创意](https://github.com/zjh-b/turtle-gallery/issues/new?template=creative_idea.yml)

目标：让观众既能欣赏作品，也能调出自己的画面、保存创作，并看懂背后的代码。优先服务社团现场展示和 GitHub 访客体验。

本路线图以 2026-09-23 的 28 款作品为起点。2026-09-24 已完成 M1：25、26 的创作面板、JSON 配方与彼岸花精修。已完成项以勾选标记；M2、M3 及后续未勾选项仍为计划，阶段编号不代表承诺完成日期。[体验 M1 与查看实测 →](CREATION_GUIDE.md)

## 已有基础与主要缺口

现有 14 款互动作品共用 `Stage` / `Paint`，已支持暂停、重置、全屏和隐藏说明；多款作品已有换色、调速、点击反馈和自动演示。Canvas 对象复用、粒子数量上限、目录导出和逻辑测试也已经具备。

25、26 现已共用创作面板和参数校验，可以用预设、滑块与构图种子设计画面，保存和载入配方。作品目录已补充互动入口类和试点能力信息。其余作品尚未接入创作模式；跨作品巡展、用户导出和网页试玩仍待实现，媒体工具仍主要面向维护者。后续继续围绕少量试点完善能力，再向其他作品扩展。

## 让画面更耐看

每件作品围绕一个主体设计配色、构图和运动。以彼岸花为例：把花簇轮廓、卷瓣和细长花丝分出层次；近处花丝摆幅稍大，远处星光更弱；绽放过程经历聚拢、展开和轻微回弹。亮部集中在花朵与交互位置，星空保留呼吸空间。

| 改进 | 实际做法 | 判断是否有效 |
| --- | --- | --- |
| 构图 | 为横屏和竖屏分别确定主体位置、题字和留白 | 缩到 320 像素宽仍能辨认主体 |
| 形态 | 花瓣加入有控制的长短差异、弯曲和遮挡 | 花朵轮廓清楚，局部变化不显杂乱 |
| 光影 | 用背景、主体、局部高光组织层次 | 灰度观察时仍能分出前后关系 |
| 动作 | 绽放、散开、回聚分别设计速度曲线 | 每次交互有可见的开始、变化和收束 |
| 连贯性 | 换主题时过渡颜色，拖动松手后平滑停下 | 连续操作时没有明显跳变 |
| 性能 | 在已有对象复用上减少静态图形重算，提供密度档位 | 同一设备上记录改动前后的帧耗时 |

新增层次时同时测量绘制成本。Tk Canvas 上的多层发光会增加对象数；高清导出可以使用单独的离线质量档位。是否引入其他渲染方案，应由试点效果和实测性能决定。

| 28 霓光蝶舞 | 点击追光、悬停与漫游、换色 | 放置多个花朵停留点；绘制飞行路线；设计对称蝶翼纹样 |
| 04 清浅荷塘 | 点击投喂、添加锦鲤 | 拖动画出水流，引导鱼群；切换雨天与晴天 |

先让一件作品的“输入 → 反馈 → 自己的结果”完整成立。新增面板应有当前数值、恢复默认和简单预设；文字输入获得焦点时，作品快捷键应正确让出输入。Tkinter 已有可用于参数面板的主题控件，可以沿用标准库。[Python 的 ttk 文档](https://docs.python.org/3/library/tkinter.ttk.html)

## 分阶段落地

### M1：创作模式与一件精修样板 · 已完成

- [x] 在共用目录中补充试点作品的入口类与参数能力，供面板、验证和媒体工具读取。
- [x] 记录精修前后的真实 Tk 帧耗时和对象数量，保留[测量数据](benchmarks/creation-m1.json)。
- [x] 为参数定义名称、范围、默认值及变化时的处理方式，先接入 25、26。
- [x] 增加可关闭、重开的滚动创作面板，提供预设、恢复默认和实时调参。
- [x] 配方保存作品 ID、格式版本、作品版本、随机种子、主题和参数。
- [x] 建立每个场景独立的随机数状态，明确“恢复配方”和“随机新作”的区别。
- [x] 精修彼岸花的轮廓、花丝层次和绽放节奏，留下[同一窗口尺寸与默认参数的版本对照](assets/lily-comparison.png)。
- [x] 为改动涉及的参数边界、重置、配方保存与恢复补充必要验证。

操作入口为作品窗口右上角的“创作面板”或 E 键。25、26 的 R 保留当前参数重新播放，“恢复默认”独立提供。配方恢复初始构图与设置，动画进度和输入历史尚未记录；PNG、短片导出属于 M2。示例、参数范围、版本约束与性能测量见[创作指南](CREATION_GUIDE.md)。

完成标准：观众能调整画面、保存配方、关闭作品再恢复；其他人拿到配方也能生成对应构图。相同版本和受支持运行环境下验证重现结果。动态回放还需要固定时间步和输入序列，仅保存随机种子并不足够；跨 Python 版本的随机算法兼容性也需要实测。[Python 随机数可重复性说明](https://docs.python.org/3/library/random.html#notes-on-reproducibility)

### M2：现场展示与带走作品

- [ ] 增加展示播放列表，支持指定顺序、单件停留时间、下一件和暂停巡展。
- [ ] 为参与巡展的作品登记自动演示能力；观众操作后暂停切换，提供明确的继续巡展入口。
- [ ] 复用启动器的子进程管理，处理自然退出、切换、关闭画廊和作品启动失败。
- [ ] 增加用户可操作的 PNG 导出，明确保存位置和实际输出尺寸。
- [ ] 为试点作品设计 16:9、9:16、1:1 构图，预览安全区域并检查题字位置。
- [ ] 大尺寸导出按目标尺寸重新绘制，检查线条与文字细节。
- [ ] 在固定时间步和输入记录可用后制作短片导出；GIF、MP4 等维护或导出依赖单独列明。

完成标准：选定作品连续巡展 10 分钟，能人工接管并继续；关闭画廊后无遗留作品进程。三种比例都能完整展示主体，画面与点击命中位置一致。导出图片的构图与预览一致。先按已实测的平台发布导出支持范围，再补充其他平台。

### M3：网页版真正可玩

- [ ] 为 01 烟花增加独立的 Canvas 试玩入口，验证点击与触摸反馈。
- [ ] 将参数、配色和说明从绘制代码中整理出来，供桌面版与网页使用。
- [ ] 通过试点再决定是否扩展 03 万花筒、26 爱心。
- [ ] 处理触摸取消、拖动越界、页面滚动和页面进入后台的情况。
- [ ] 提供键盘可操作的控制按钮、静态预览和减少动态效果的选项。
- [ ] 对桌面版和网页版共享的公式或参数，用固定样例比较结果。

这是为选定作品开发浏览器实现，涉及额外的渲染和输入维护。Canvas 适合二维动画；Pointer Events 可统一处理鼠标、触控笔和触摸。控件和重要说明放在语义化 HTML 中，便于键盘操作与辅助工具读取。[Canvas 文档](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API) · [Pointer Events 示例](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Using_Pointer_Events)

完成标准：在实际手机和桌面浏览器中都能完成一次互动；窄屏没有横向溢出；离开页面后停止不必要的绘制。保留明确的桌面运行入口，并标记哪些作品已经支持在线试玩。

### M4：降低持续维护成本

- [ ] 为互动作品补充可选的入口类、能力、预设及演示信息，让测试和媒体工具读取同一份注册信息。
- [ ] 在试点中逐步拆分状态更新与绘图，支持实时播放和固定时间步导出。
- [ ] 从重复的花瓣曲线、星空和过渡计算中提取小型共用函数。
- [ ] 提供最小作品示例与添加步骤，新作品能复用面板、配方和通用操作。
- [ ] 检查目录导出与源数据一致，验证预览路径、作品 ID 和资源存在性。
- [ ] 为媒体缓存记录源码、共用舞台、渲染工具及参数的变化，避免使用过期截图。
- [ ] 在现有 Windows / Linux 逻辑检查之外，逐步建立真实 GUI 和浏览器检查；平台支持注明实测范围。

这些维护工作随 M1–M3 的实际需要穿插推进。现有 `frame(dt)` 可以先通过适配保留；当两个作品确实需要同一个能力时，再提取共用接口。

当前可从 [作品目录.py](../社团展示/作品目录.py)、[舞台.py](../社团展示/舞台.py)、[媒体工具](../tools/render_media.py) 和 [作品测试](../tests/test_demos.py) 入手。入口登记支持统一配置；配置、时间步与输入记录支持重复捕获；捕获与构图再支持分享导出。目录一致性检查可并行推进。

完成标准：新增一个互动作品时，入口类和能力只需登记一次；预览工具与基础检查能发现它。修改共用代码后，相关媒体资源能判定为需要更新；画面问题有相同种子和时间点的对照图可查。

## 每轮更新怎样验收

每个小版本选择一个主要体验目标，配套一个成熟作品和对应预览、说明。例如“保存自己设计的彼岸花”比同时引入多个未完成的交互更容易验证。

| 维度 | 检查方式 | 建议目标，尚非测量结果 |
| --- | --- | --- |
| 初次上手 | 请 3–5 位没看过说明的同学试玩并记录卡住的位置 | 10 秒内找到第一种互动 |
| 观赏性 | 相同尺寸、种子和时间点对比改动前后；请同学描述主体与变化 | 主体易辨认，动态不遮挡关键信息 |
| 性能 | 记录系统、Python/Tk、窗口尺寸、质量档位和帧耗时 | 基准设备上默认档位争取 95% 帧间隔不超过 33 毫秒 |
| 持续展示 | 连续运行 10 分钟，期间操作、切换和重置 | 交互持续响应，对象数量受控，资源占用趋于稳定 |
| 创作复用 | 保存、关闭、重开并恢复配方 | 对应参数与构图能重现，格式不兼容时提示明确 |
| 使用范围 | 在声明支持的平台与尺寸实际运行 | 记录实测结果，修复阻断使用的问题 |

先收集一轮基线，再决定优先改哪里。Star 数可以观察项目传播，作品能否顺利运行、观众是否完成互动、是否愿意保存自己的结果，更适合指导产品修改。
