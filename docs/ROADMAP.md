## 已有基础与主要缺口

现有 31 款作品（17 款互动展品与 14 个创意原作）共用 `Stage` / `Paint`，已支持暂停、重置、全屏和隐藏说明；多款作品已有换色、调速、点击反馈和自动演示。Canvas 对象复用、粒子数量上限、目录导出和逻辑测试也已经具备。

新增 29 极光之境、30 机械星仪、31 水晶花园：以湖面极光、金属环带和晶体切面扩展桌面艺术展品。三件均支持三种主题、调速与点击互动，作品目录、网页预览和创作说明同步收录；配方、自动巡展与网页试玩仍沿用下述已有试点范围。[画面与操作 →](IMMERSIVE_ART.md)

25、26 现已共用创作面板和参数校验，可以用预设、滑块与构图种子设计画面，保存和载入配方，并在 Windows 导出当前画面 PNG；横屏、竖屏和方形支持 1080 / 2160 高清重绘。25、26、27 可按指定顺序循环巡展。作品目录已登记互动入口类、创作与自动演示能力，01 烟花、03 万花筒与 26 粒子爱心已有独立网页试玩。其余作品尚未接入在线试玩；25、26 已有固定时间步的竖屏短片导出工具，详见[视频制作指南](VIDEO_EXPORT.md)。后续继续围绕少量试点完善能力，再向其他作品扩展。

## 让画面更耐看

每件作品围绕一个主体设计配色、构图和运动。以彼岸花为例：把花簇轮廓、卷瓣和细长花丝分出层次；近处花丝摆幅稍大，远处星光更弱；绽放过程经历聚拢、展开和轻微回弹。亮部集中在花朵与交互位置，星空保留呼吸空间。

| 改进 | 实际做法 | 判断是否有效 |
| --- | --- | --- |
| 构图 | 为横屏和竖屏分别确定主体位置、题字和留白 | 缩到 320 像素宽仍能辨认主体 |
| 形态 | 花瓣加入有控制的长短差异、弯曲和遮挡 | 花朵轮廓清楚，局部变化不显杂乱 |
| 光影 | 用背景、主体、局部高光组织层次 | 灰度观察时仍能分出前后关系 |
| 动作 | 绽放、散开、回聚分别设计速度曲线 | 每次交互有可见的开始、变化和收束 |
| 连贯性 | 换主题时过渡颜色，拖动松手后平滑停下 | 连续操作时没有明显跳变 |
| 性能 | 在已有对象复用上减少静态图形重算，提供密度档位 | 同一设备上记录改动前后的帧耗时 |

新增层次时同时测量绘制成本。Tk Canvas 上的多层发光会增加对象数；高清导出可以使用单独的离线质量档位。是否引入其他渲染方案，应由试点效果和实测性能决定。

## 让互动变成创作

| 作品 | 已有互动 | 可以继续扩展的玩法 |
| --- | --- | --- |
| 25 星空彼岸花 | 点击流星、重播绽放；面板调整花色、速度、卷曲、微风与星空密度；保存配方 | 拖动产生局部微风，让花丝跟随观众动作缓动 |
| 26 怦然心动 | 点击散开再聚合；面板调整配色、心跳、粒子数量和大小；保存配方 | 鼠标附近粒子避让；粒子在心形与社团名字之间变换；保存文字 |
| 27 星河玫瑰 | 点击星尘、重播绽放、换色、调速 | 拖动观察轻微视差；控制花瓣展开程度；组合多支花的布局 |
| 28 霓光蝶舞 | 点击追光、悬停与漫游、换色 | 放置多个花朵停留点；绘制飞行路线；设计对称蝶翼纹样 |
| 04 清浅荷塘 | 点击投喂、添加锦鲤 | 拖动画出水流，引导鱼群；切换雨天与晴天 |
| 09 几何绘图仪 | 选择曲线、逐笔重绘、显示圆盘、调速 | 滑块调半径比与偏心距；显示轨迹闭合关系；保存纹样配方 |

先让一件作品的“输入 → 反馈 → 自己的结果”完整成立。新增面板应有当前数值、恢复默认和简单预设；文字输入获得焦点时，作品快捷键应正确让出输入。Tkinter 已有可用于参数面板的主题控件，可以沿用标准库。[Python 的 ttk 文档](https://docs.python.org/3/library/tkinter.ttk.html)

### M1：创作模式与一件精修样板 · 已完成

- [x] 在共用目录中补充试点作品的入口类与参数能力，供面板、验证和媒体工具读取。

- [x] 为参数定义名称、范围、默认值及变化时的处理方式，先接入 25、26。

- [x] 配方保存作品 ID、格式版本、作品版本、随机种子、主题和参数。
- [x] 建立每个场景独立的随机数状态，明确“恢复配方”和“随机新作”的区别。
- [x] 精修彼岸花的轮廓、花丝层次和绽放节奏，留下[同一窗口尺寸与默认参数的版本对照](assets/lily-comparison.png)。
- [x] 为改动涉及的参数边界、重置、配方保存与恢复补充必要验证。

操作入口为作品窗口右上角的“创作面板”或 E 键。25、26 的 R 保留当前参数重新播放，“恢复默认”独立提供。配方恢复初始构图与设置，动画进度和输入历史尚未记录。当前画面 PNG 已由 M2 接入同一面板；25/26 另有独立的固定脚本[短片制作工具](VIDEO_EXPORT.md)。示例、参数范围、版本约束与性能测量见[创作指南](CREATION_GUIDE.md)。

完成标准：观众能调整画面、保存配方、关闭作品再恢复；其他人拿到配方也能生成对应构图。相同版本和受支持运行环境下验证重现结果。动态回放还需要固定时间步和输入序列，仅保存随机种子并不足够；跨 Python 版本的随机算法兼容性也需要实测。[Python 随机数可重复性说明](https://docs.python.org/3/library/random.html#notes-on-reproducibility)

这些维护工作随 M1–M3 的实际需要穿插推进。现有 `frame(dt)` 可以先通过适配保留；当两个作品确实需要同一个能力时，再提取共用接口。

完成标准：新增一个互动作品时，入口类和能力只需登记一次；预览工具与基础检查能发现它。修改共用代码后，相关媒体资源能判定为需要更新；画面问题有相同种子和时间点的对照图可查。

## 每轮更新怎样验收

每个小版本选择一个主要体验目标，配套一个成熟作品和对应预览、说明。例如“保存自己设计的彼岸花”比同时引入多个未完成的交互更容易验证。

| 维度 | 检查方式 | 建议目标，尚非测量结果 |
| --- | --- | --- |
| 初次上手 | 请 3–5 位没看过说明的同学试玩并记录卡住的位置 | 10 秒内找到第一种互动 |
| 观赏性 | 相同尺寸、种子和时间点对比改动前后；请同学描述主体与变化 | 主体易辨认，动态不遮挡关键信息 |
| 性能 | 记录系统、Python/Tk、窗口尺寸、质量档位和帧耗时 | 基准设备上默认档位争取 95% 帧间隔不超过 33 毫秒 |
| 持续展示 | 连续运行 10 分钟，期间操作、切换和重置 | 交互持续响应，对象数量受控，资源占用趋于稳定 |
| 创作复用 | 保存、关闭、重开并恢复配方 | 对应参数与构图能重现，格式不兼容时提示明确 |
| 使用范围 | 在声明支持的平台与尺寸实际运行 | 记录实测结果，修复阻断使用的问题 |

先收集一轮基线，再决定优先改哪里。Star 数可以观察项目传播，作品能否顺利运行、观众是否完成互动、是否愿意保存自己的结果，更适合指导产品修改。
